# Feature Specification: 可靠点击与点击落光标

**Feature Branch**: `001-reliable-click-caret`（规格目录；分支策略由仓库所有者决定）

**Created**: 2026-11-25

**Status**: Draft

**Input**: User description: "点击表格最后位置后表格变成源码状态没问题，但此时点击正文那一行会卡住（偶发、多次）。点击正文任意位置需要先点一下转成源码模式、光标落在最后，再二次定位——应当点哪里光标就落在哪里。编辑操作体验对标 Obsidian / Typora。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一次点击一次生效 (Priority: P1)

用户正在编辑某一段正文（或某个表格单元格），想去编辑别处——比如表格里的某个单元格、表格旁的空白、另一段正文。
他点击目标，期望这一次点击就完成切换：原位置已输入的内容被保留，目标立即进入编辑态并出现光标，
接下来敲字就落在光标处。不需要"先点一下没反应、再点一下才行"。

**Why this priority**: 这是"卡住"类问题中已实证复现的部分：从编辑中的块去点表格单元格时，
点击会被静默吞掉，焦点掉回空白，用户看到的就是"点了没反应、卡住了"。它直接破坏最核心的编辑动作。

**Independent Test**: 在正文中点击进入编辑态 → 单击表格的某个单元格 → 单元格必须立即进入编辑态、持有焦点，
随后输入的字符出现在该单元格内。换"点击表格旁空白""点击另一段正文""目标原先是单元格编辑态"重复。

**Acceptance Scenarios**:

1. **Given** 某段正文处于编辑态且拥有光标， **When** 用户单击表格中任一单元格， **Then** 该单元格进入编辑态并拥有光标，原段落保留已输入内容并退出编辑态
2. **Given** 某个单元格处于编辑态， **When** 用户单击表格旁空白， **Then** 整表进入源码编辑态并拥有光标
3. **Given** 任意编辑状态（含无编辑）， **When** 用户单击另一处可编辑目标， **Then** 恰好该目标处于编辑态并拥有焦点，不存在"没有目标获得焦点"的结果
4. **Given** 用户在正文中输入了若干字符， **When** 点击别处切换目标， **Then** 已输入字符完整保留

---

### User Story 2 - 点哪里，光标落在哪里 (Priority: P1)

用户看到渲染好的正文，想在某一行中间的某个字前后插入文字。他在那个位置单击一次，
期望该处立即出现光标（所在块同时进入源码编辑态），随后敲字就插在那个位置。
不需要先点一下让光标落到行尾、再在源码里点第二次。

**Why this priority**: 这是用户明确提出的核心体验诉求，也是与成熟编辑器最直观的差距。

**Independent Test**: 打开含标题、列表、引用、粗体、行内代码、链接的多段落文档，
在各行的前/中/后位置单击，逐次核对光标是否落在被点击字符的前或后（按点击落在字符的前半/后半）。

**Acceptance Scenarios**:

1. **Given** 一个渲染态段落"你好世界"， **When** 用户单击"世"字的左半边， **Then** 光标出现在"世"之前，输入"X"后得到"你好X世界"
2. **Given** 渲染态段落"前面**粗体**后面"， **When** 用户单击"粗"字左半边， **Then** 光标位于源码中"**"之后、"粗"之前（输入的文字是粗体的一部分）
3. **Given** 一个三行的列表， **When** 用户单击第二行中间， **Then** 光标在第二行该位置，而不是列表末尾
4. **Given** 渲染态标题"# 标题文字"， **When** 用户单击行首"标"字左侧， **Then** 光标位于"# "之后
5. **Given** 渲染态表格， **When** 用户单击表格第二行右侧的空白处， **Then** 整表进入源码编辑态，光标位于源码第二行行尾

---

### User Story 3 - 连续手势不打断 (Priority: P2)

用户在渲染态正文上按下鼠标后直接拖动，期望像在普通文本框里一样选中一段文字；
或者双击某个词，期望选中的就是他看到的那个词（包括中文词）。
这两种手势都必须在"第一次按下"时就成立，不需要先单击一次进入编辑态。

**Why this priority**: 选中文字是紧随定位光标的第二高频编辑手势；若首次按下后拖动/双击无效，
点击落光标的体验只完成了一半。

**Independent Test**: 在从未点击过的渲染态段落上：按下→拖过三个字→松开，选区恰为这三个字；
双击某个中文词，选区恰为该词。

**Acceptance Scenarios**:

1. **Given** 渲染态段落未被点击过， **When** 用户在第 2 个字处按下并拖到第 5 个字后松开， **Then** 第 2–5 个字被选中
2. **Given** 渲染态段落含"输入法组合"， **When** 用户双击"组合"， **Then** 选区恰为"组合"二字
3. **Given** 编辑态块内， **When** 用户再次双击/三击， **Then** 保持系统原生选词/选段行为

---

### User Story 4 - 输入法友好 (Priority: P2)

中文用户用拼音输入法连续输入多个词、中途切走、或提交后立即点击别处，
期望组合文本正确上屏、原位置光标正常、新位置可立即输入，不出现残留拼音、丢字或"有光标却打不了字"。

**Why this priority**: 目标用户以中文输入为主；输入法过程涉及引擎内部时序，出错时表现正是"打字没反应"。

**Independent Test**: 用输入法协议模拟"标记→标记→提交"三个词，每步后输入一个字母，核对文档内容与光标位置；
再覆盖"标记未提交时点击别处"。

**Acceptance Scenarios**:

1. **Given** 段落处于编辑态， **When** 用户连续用拼音输入三个词， **Then** 文档内容为原文加三个词，光标在第三个词之后，继续输入有效
2. **Given** 输入法组合尚未提交， **When** 用户点击另一段， **Then** 新段获得光标并可输入
3. **Given** 在表格源码编辑态完成一次中文输入， **When** 用户点击正文段落， **Then** 正文段落获得光标并可输入

---

### User Story 5 - 偶发问题可追溯 (Priority: P3)

用户再次遇到"卡住"时，希望能把编辑器最近的状态变化导出来交给开发者定位，
而不是只能描述"点了某处就卡了"。若编辑器本身已无响应，系统应明确告知，而不是无限等待。

**Why this priority**: 用户的原始问题属于偶发且未能在自动化环境中复现；
没有现场记录，下次发生仍然无从下手。

**Independent Test**: 做几次点击/输入后执行"帮助"菜单里的导出命令，剪贴板中出现含时间戳的状态记录；
模拟编辑器无响应时执行该命令，数秒内出现明确提示。

**Acceptance Scenarios**:

1. **Given** 用户做了若干次点击与输入， **When** 执行"导出编辑器诊断信息"， **Then** 剪贴板包含最近的状态切换记录与当前一致性检查结果
2. **Given** 编辑器线程无响应， **When** 执行同一命令， **Then** 5 秒内提示"编辑器无响应"，应用其余部分仍可操作

## Edge Cases

- 点击落在块的上/下外边距（块与块之间的空白）：沿用现有空白区行为（进入相邻块或在其后新建空段）。
- 点击落在块内行尾右侧的空白或块的下边缘：归入该行行尾，不得被当成块外空白。
- 目标块已处于编辑态：交给系统原生光标定位，不做二次转换。
- 代码块、公式块、分隔线、front matter、脚注定义的点击行为保持不变。
- 行内含图片：点击图片仍是预览；点击图片前后的文字正常落光标。行内公式：光标落在公式源码的对应一侧。
- 链接：单击落光标；⌘点击或右键菜单打开（行为变更，见假设）。任务勾选框：点击仍为切换完成状态。
- 点击时存在未提交的输入法组合：先按系统规则结束组合并保留已上屏内容，再执行切换。
- 空块、仅含语法符号的块、超长行：不得报错，光标退化为块首或块尾。
- 渲染态与源码态文字宽度不同造成的视觉位移：落点以逻辑位置为准。
- 表格放大视图、图片预览等浮层打开期间：点击不穿透到文档。
- 键盘导航（方向键跨界、Esc 提交、Enter 拆块）、查找栏、侧栏行为不变。

## Requirements *(mandatory)*

### Functional Requirements

**A. 点击生效**

- **FR-001**: 用户单击处于渲染态的文本块或表格单元格时，系统 MUST 在该次点击内使目标进入编辑态并获得焦点；
  无论此前处于何种编辑状态（正文编辑中、单元格编辑中、表格源码编辑中、代码编辑中、无编辑）。
- **FR-002**: 一次点击 MUST 至多触发一次目标切换，MUST NOT 产生"点击后没有任何目标获得焦点"的结果。
- **FR-003**: 点击块内空白 MUST 归入最近的那一行/块，MUST NOT 被判定为块外空白。

**B. 点击落点**

- **FR-004**: 单击渲染态文本上的某个字符时，光标 MUST 落在该字符对应的源码位置：
  点击点在字符前半 → 光标在该字符之前；后半 → 之后。
- **FR-005**: 渲染态不可见的语法符号（标题井号、列表符号、引用符、粗斜体定界符、链接地址与括号、
  行内代码反引号、图片整段、公式美元符、任务勾选框、转义反斜杠）MUST NOT 成为光标落点；
  点击落在这些位置时，光标 MUST 落在相邻可见字符一侧。
- **FR-006**: 多行块中，光标 MUST 落在被点击的那一行。
- **FR-007**: 点击表格旁空白 MUST 进入整表源码编辑，光标落在被点击行的行尾（表格上方 → 源码开头；下方 → 源码结尾）。
- **FR-008**: 进入编辑态后，用户 MUST 能立即输入，输入内容 MUST 落在光标处。
- **FR-009**: 单击链接文字 MUST 落光标；打开链接 MUST 通过 ⌘点击或右键菜单完成。
- **FR-010**: 双击 MUST 选中被双击的词（以渲染态所见文字为准，支持中文分词）。
- **FR-011**: 在未进入编辑态的块上按下并拖动，MUST 以按下点为锚、按拖动范围扩展选区（首次按下即生效）。

**C. 状态一致**

- **FR-012**: 任意时刻若某块或单元格处于编辑态，它 MUST 是当前焦点元素，且光标或选区位于其内。
- **FR-013**: 每次处理鼠标按下之前，系统 MUST 校验并修复不一致：
  对已失去焦点或光标的编辑态，MUST 先完整保存其内容再清除登记，然后才执行本次点击。
- **FR-014**: 输入法组合的提交/取消过程中，系统 MUST NOT 在引擎写入最终文本之前改写编辑中的内容
  （立项时怀疑此处有隐患；实测现有实现已满足，故不改代码，以回归用例守卫——见 research.md RQ-006）。
- **FR-015**: 任何状态切换或一致性修复 MUST 保留用户已输入的文本。

**D. 可诊断**

- **FR-016**: 系统 MUST 记录最近不少于 60 次编辑器状态切换（进入/提交编辑、焦点变化、光标位置、输入法组合事件），带时间戳。
- **FR-017**: 用户 MUST 能通过一个菜单命令把上述记录与当前一致性检查结果复制到剪贴板；
  编辑器无响应时，MUST 在 5 秒内明确提示。

### Key Entities

- **编辑会话**: 某一时刻唯一的"正在编辑"对象——块级源码、表格单元格、代码编辑器三选一；含目标与内容。
- **落点映射**: 渲染态可见文字位置 ↔ 源码字符位置之间的对应关系；不可见语法不占可见位置。
- **一致性不变量**: "登记为编辑中" ⇔ "拥有焦点且光标在其内"。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从任意编辑状态单击表格单元格，一次点击生效率为 100%（修复前随机序列实测：300 条中 134 条、约 45% 出现被吞）。
- **SC-002**: 点击落光标用例集（标题/列表/引用/多行段落/粗体/行内代码/链接/表格旁空白）逐例核对，落点正确率 100%。
- **SC-003**: 不少于 300 条随机操作序列（点击/双击/拖动/输入/快捷键）中，
  "有编辑态但输入不落地"与"点击被吞"发生次数为 0。（实测：300 条，0 次；修复前同种子 134 次。
  立项时写的 400 条含输入法协议步骤，实测输入法处理无缺陷后未纳入随机序列，改由定向场景覆盖。）
- **SC-004**: 现有全部自动化测试与构建保持通过。
- **SC-005**: 单击到光标出现的处理耗时不超过 50 毫秒（不含系统渲染）。
- **SC-006**: 连续三次拼音输入（标记→标记→提交）后，文档内容与光标位置全部正确。

## Assumptions

- 用户所说的"卡住"按"编辑区失去焦点、点击无效或输入不落地"处理。该确切路径未能在自动化环境复现
  （250 条随机序列 + 23 个定向场景，含切换应用、慢点击、双击、输入法组合），
  因此除修复已实证的缺陷外，以一致性校验与自愈（FR-012/013）覆盖同类未知路径，并提供诊断导出（FR-016/017）。
- 单击链接的行为从"直接打开"改为"落光标，⌘点击打开"，对标 Typora；右键"打开链接"保留。
- 输入法：调查中未发现现有实现的缺陷（曾因探针台自身的调用约定错误两次误判），本次不做行为改动。
- 诊断命令放在应用菜单（BlockMark 子菜单），名称"导出编辑器诊断信息"。
- 保持"整块显示源码"的编辑模型不变，只改变光标落点；源码态下不可见的语法符号可见造成的视觉位移不在本次范围内。
- 诊断信息只复制到剪贴板，不写文件、不联网。
- 本次不自动部署到 /Applications，不提交、不推送、不发版，均由仓库所有者决定。
